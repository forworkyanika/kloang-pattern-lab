โปรแกรมนี้ทำไปเพื่ออะไร

กลบทคือโคลงที่มี “กฎเพิ่ม” ซ้อนบนฉันทลักษณ์ปกติ เช่น ต้องซ้ำคำที่ตำแหน่งหนึ่ง หรือคำท้ายบาทต้องเป็นคำแรกของบาทถัดไป โปรแกรมนี้แปลงกฎเหล่านั้นให้เป็นโครงสร้างทางคณิตศาสตร์ที่คอมพิวเตอร์ตรวจได้ เพื่อใช้ศึกษาและเตรียมข้อมูลก่อนเทรนโมเดล

① นิยามกลบทให้ตรวจได้

แทนกลอนด้วย “กลุ่มตำแหน่งที่เป็นคำเดียวกัน” (partition) แล้วดึงเป็นกฎ เช่น บ1.ว0.0 = บ2.ว0.0 ซึ่งไม่ขึ้นกับคำศัพท์

② สร้างชุดข้อมูลกลบท

รวมกลบทคลาสสิกจากจารึกวัดพระเชตุพนฯ และจินดามณี พร้อมที่มา ตรวจว่าแต่ละบทเข้ากับลายของชนิดตัวเองจริง

③ ประเมินก่อนเทรน LoRA

วัดว่าลายแต่ละแบบ “สอน” อะไรให้โมเดล — ระยะคัดลอก คำซ้ำบังเอิญ ความหลากหลายของลาย — ก่อนเสียเวลา GPU

④ เรียนรู้ความปลอดภัย

ใช้ตัวตรวจลายเป็นเครื่องมือป้องกันข้อมูลปนเปื้อน และฝึกแนวปฏิบัติด้าน security ของการ fine-tune

ขั้นตอนการใช้งาน

  1. ทดลอง — ใส่กลอนเอง หรือใช้ 12 บทตัวอย่าง ติ๊ก “ต้นแบบ” เพื่อดึงกฎ และติ๊ก “ทดสอบ” เพื่อตรวจ
  2. วิเคราะห์ผลต่อ LoRA — ดูว่าลายของแต่ละบท/แต่ละชนิดจะส่งผลต่อการเรียนของโมเดลอย่างไร และควรแก้ข้อมูลตรงไหน
  3. คณิตศาสตร์ — นิยามและทฤษฎีที่อยู่เบื้องหลังทุกตัวเลขในหน้าจอ
  4. Security × LoRA — เทคนิคป้องกันที่ประยุกต์กับโครงการนี้ พร้อมเครื่องมือตรวจชุดข้อมูล

Negative control (ลายเสีย) คืออะไร

กลุ่มควบคุม (control) คือตัวอย่างที่เรารู้คำตอบล่วงหน้า ใช้พิสูจน์ว่าเครื่องมือวัดทำงานถูก เหมือนชุดตรวจโควิดที่มีแถบควบคุม ถ้าตัวตรวจให้ “ผ่าน” กับทุกอย่าง มันก็ไร้ประโยชน์ — negative control มีไว้จับปัญหานี้

ขอบเขตการใช้งาน

โปรแกรมนี้จัดทำเพื่อการศึกษาเท่านั้น ไม่มีเจตนาอื่น ไม่ได้เทรนโมเดลจริงในเบราว์เซอร์ และไม่เก็บข้อมูลใดออกนอกเครื่อง (ข้อมูลอยู่ใน localStorage ของเบราว์เซอร์) เนื้อหาด้าน security เป็นมุมมองฝั่งป้องกัน ตัวอย่างกลอนเป็นงานคลาสสิกที่พ้นอายุลิขสิทธิ์ การแบ่งพยางค์ทำโดยผู้พัฒนาและควรตรวจกับต้นฉบับก่อนใช้อ้างอิง

        Mathematical formulation

        ทุกตัวเลขในโปรแกรมมาจากแนวคิดเดียว: ลายของกลบท = การแบ่งตำแหน่งออกเป็นกลุ่มคำเดียวกัน (set partition) ส่วนที่เหลือคือวิธีเขียน ตรวจ เปรียบเทียบ และนับ partition นั้น

        §1 กลอนเป็นฟังก์ชันบนเซตตำแหน่ง

        ให้เซตตำแหน่งของกลอนหนึ่งบทเป็น

        $$P=\{(b,w,k)\},\qquad b\in\{1,\dots,4\}\ (\text{บาท}),\; w\in\{0,1,2\}\ (\text{วรรค}),\; k\ (\text{ลำดับในวรรค})$$

        เรียงตามลำดับการอ่าน (lexicographic) \(p_1\prec p_2\prec\dots\prec p_N\) และเขียนดัชนี \(i(p)\) กลอนคือฟังก์ชัน

        $$x:P\to\Sigma$$

        โดย \(\Sigma\) คือคลังพยางค์ เช่น \(x(1,0,0)=\text{ผล}\) ในโปรแกรม \(P\) คือผลของ flattenWithPos

        §2 โครงสร้าง = partition จาก kernel ของ \(x\)

        $$p\sim_x q \iff x(p)=x(q),\qquad \Pi(x)=P/{\sim_x}$$

        ทฤษฎีบท (ไม่แปรเปลี่ยนต่อการเปลี่ยนคำ) ถ้า \(\sigma:\Sigma\to\Sigma'\) เป็นฟังก์ชันหนึ่งต่อหนึ่ง แล้ว

        $$\Pi(\sigma\circ x)=\Pi(x)$$

        พิสูจน์ \(\sigma(x(p))=\sigma(x(q))\iff x(p)=x(q)\) เพราะ \(\sigma\) หนึ่งต่อหนึ่ง ∎ — นี่คือเหตุผลที่ positive control (เปลี่ยนคำทุกคำ) ยังได้ลายเดิม

        §3 รหัสมาตรฐาน 3 แบบที่เทียบเท่ากัน

        First-occurrence (Method 4):

        $$f(p)=\min_{\prec}\{\,q\in P : x(q)=x(p)\,\}$$

        Restricted growth string (ลายตัวอักษร A B B C …):

        $$r(p)=\bigl|\{\,f(q): q\preceq p\,\}\bigr|,\qquad r(p_1)=1,\quad r(p_{j+1})\le 1+\max_{i\le j} r(p_i)$$

        Prev-encoding (Method 5 · Baker 1993):

        $$d(p)=\begin{cases} i(p)-\max\{\,i(q): q\prec p,\ x(q)=x(p)\,\} & \text{ถ้ามี}\\ 0 & \text{ถ้าพบครั้งแรก}\end{cases}$$

        ข้อเสนอ \(f\), \(r\), \(d\) แต่ละตัวกำหนด \(\Pi(x)\) ได้ครบและกลับทางได้: จาก \(f\) กลุ่มคือ \(\{p: f(p)=c\}\); จาก \(d\) ให้ลากเส้นจากแต่ละ \(p\) ไปยังตำแหน่ง \(i(p)-d(p)\) ได้สายโซ่ซึ่งแต่ละสายคือกลุ่มหนึ่ง ∴ Method 4 กับ 5 เก็บข้อมูลเท่ากันเสมอ ต่างกันที่ \(f\) เป็นตำแหน่งสัมบูรณ์ ส่วน \(d\) เป็นระยะสัมพัทธ์ (ใช้ดูลายที่เลื่อนตำแหน่งได้ เช่น ซ้ำสองแสนง)

        §4 Equality matrix

        $$E_{pq}=[\,x(p)=x(q)\,]=(ZZ^{\top})_{pq},\qquad Z\in\{0,1\}^{N\times|\Sigma|}\ \text{(one-hot)}$$

        ดังนั้น \(E\succeq 0\) และ \(\operatorname{rank}E=|\Pi(x)|\) ถ้าจัดเรียงแถวตามกลุ่ม \(E\cong\bigoplus_j J_{n_j}\) (บล็อกเลข 1 ขนาดเท่ากลุ่ม) ค่าเฉพาะที่ไม่เป็นศูนย์คือขนาดกลุ่ม \(n_j\) — ดาวล้อมเดือน: \(N=32\), \(|\Pi|=25\), กลุ่ม ผล มีขนาด 4 และ บุญ บาป คง… คู่ละ 2

        §5 กฎ = spanning forest ของแต่ละกลุ่ม

        $$R(x)=\{\,(f(p),p): p\ne f(p)\,\},\qquad |R(x)|=N-|\Pi(x)|$$

        ดาวล้อมเดือน: \(32-25=7\) กฎ การปิดทางสมมูล (equivalence closure) ของ \(R\) ให้ \(\sim_x\) คืนมาครบ จึงไม่มีข้อมูลหาย กฎแบ่งเป็น SAME (\(b\) เดียวกัน) และ CROSS (ข้ามบาท)

        §6 ตัวตรวจ = ลำดับบน partition

        $$s(y;R)=\frac{1}{|R|}\sum_{(a,b)\in R}[\,y(a)=y(b)\,]$$ $$s(y;R)=1\iff \sim_R\subseteq\ \sim_y\iff \Pi_R\preceq\Pi(y)$$

        คือ partition ของกฎ ละเอียดกว่าหรือเท่ากับ ของกลอนที่ตรวจ — กลอนจึงมีคำซ้ำเพิ่ม (คำซ้ำบังเอิญ) ได้โดยไม่เสียคะแนน ส่วน “ลายตรงทุกตัว” คือกรณี \(\Pi(y)=\Pi_R\) ซึ่งเข้มเกินไปสำหรับกลอนจริง

        §7 กฎร่วมของหลายบท = meet ใน partition lattice

        $$\Pi_1\wedge\Pi_2\ \leftrightarrow\ \sim_1\cap\sim_2,\qquad R_T=R\Bigl(\bigwedge_{i\in T}\Pi_i\Bigr)$$

        อินเตอร์เซกชันของความสัมพันธ์สมมูลยังเป็นความสัมพันธ์สมมูล จึงได้ partition ใหม่ที่เก็บเฉพาะคู่ที่ “ทุกบท” ซ้ำเหมือนกัน คำซ้ำบังเอิญหายไป — ตัวอย่าง: ซ้ำสองแสนงสองบทเหลือกฎร่วมเพียง 1 ข้อ เพราะตำแหน่งคำซ้ำแปรผัน

        §8 นับลาย และวัดปริมาณข้อมูลของข้อบังคับ

        จำนวนลายทั้งหมดบน \(N\) ตำแหน่งคือ Bell number \(B_N\):

        $$B_{32}\approx1.28\times10^{26},\qquad \#\{\Pi:\Pi_R\preceq\Pi\}=B_{|\Pi_R|}=B_{25}\approx4.64\times10^{18}$$

        ลายที่ผ่านกฎดาวล้อมเดือนจึงมีเพียงราว \(3.6\times10^{-8}\) ของทั้งหมด ถ้าสุ่มพยางค์อิสระจากคลังขนาด \(V\) โอกาสผ่านกฎทุกข้อคือ

        $$\Pr[s(y;R)=1]=V^{-|R|}\quad\Rightarrow\quad I(R)=|R|\log_2 V\ \text{bits}$$

        (แต่ละกฎใน forest บังคับ 1 ตำแหน่งให้เท่ากับรากของกลุ่ม) — คอลัมน์ “ข้อมูลข้อบังคับ (bits)” ในแท็บ LoRA คือค่านี้

        §9 ระยะห่างระหว่างกลอน

        $$d_H(r^{(1)},r^{(2)})=\sum_{j}[\,r^{(1)}_j\ne r^{(2)}_j\,]\ \ (\text{ยาวเท่ากัน}),\qquad d_{\text{Lev}}\ \ (\text{ยาวไม่เท่า})$$

        หรือใช้ \(1-s(y;R)\) เป็นระยะแบบไม่สมมาตรจาก “ลายต้นแบบ” ไปยังกลอน

        §10 เชื่อมกับ LoRA

        LoRA (Hu et al., 2021) ตรึงน้ำหนักเดิม \(W_0\) และเรียนเฉพาะส่วนเพิ่ม rank ต่ำ:

        $$W=W_0+\Delta W,\qquad \Delta W=\tfrac{\alpha}{r}BA,\quad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k},\ \operatorname{rank}\Delta W\le r$$

        ฝึกด้วย cross-entropy ของ token ถัดไป:

        $$\mathcal{L}(B,A)=-\sum_{t}\log p_{\theta}(y_t\mid y_{\lt t})$$

        กฎ = งานคัดลอก การทำตามกฎ \((a,b)\) หมายความว่าโมเดลต้องให้ความน่าจะเป็นสูงกับ \(y_b=y_a\) คือ “คัดลอกจากระยะ \(d(b)\) ก่อนหน้า” ซึ่งใน Transformer ทำผ่าน attention gradient ที่ปรับ \(B,A\) จึงมาจากตำแหน่งเป้า \(T_R=\{b:(a,b)\in R\}\) เป็นหลัก สัดส่วนตำแหน่งที่มีสัญญาณคือ

        $$\rho=\frac{|R|}{N}\quad(\text{ดาวล้อมเดือน } 7/32\approx0.22)$$

        ถ้าต้องการเน้นลาย ใช้ loss ถ่วงน้ำหนัก

        $$\mathcal{L}_w=-\sum_t w_t\log p_\theta(y_t\mid y_{\lt t}),\qquad w_t=1+\lambda\,[\,t\in T_R\,]$$

        ข้อควรระวัง LLM ไม่ได้ตัดเป็นพยางค์ ให้ \(\tau\) เป็น tokenizer ระยะใน token มักยาวกว่าระยะในพยางค์ และกฎต้องแปลงผ่าน \(\tau\) ก่อนใช้กับ \(T_R\) จริง งาน GPoeT (Popescu-Belis et al., 2023) พบว่าลายสัมผัสระยะใกล้ (AABB) เรียนได้ง่ายกว่าระยะไกล (ABAB) — สอดคล้องกับการดูการกระจายของ Δ

        §11 ความหลากหลายของลายในชุดข้อมูล (เชิงชี้นำ)

        สร้างเมทริกซ์ลักษณะ \(M\in\{0,1\}^{n\times m}\): แถว = กลอน, คอลัมน์ = คู่ตำแหน่ง \((p,q)\), \(M_{ij}=1\) ถ้ากลอน \(i\) มี \(x(p)=x(q)\) หา singular values \(\sigma_1\ge\sigma_2\ge\dots\) แล้ว

        $$\operatorname{erank}(M)=\exp\Bigl(-\sum_i \hat\sigma_i\ln\hat\sigma_i\Bigr),\qquad \hat\sigma_i=\frac{\sigma_i}{\sum_j\sigma_j}$$

        erank บอกว่าชุดข้อมูลมี “ทิศทางของลาย” ที่เป็นอิสระต่อกันประมาณกี่ทิศ ถ้าเกือบทุกบทเป็นลายเดียวกัน erank ≈ 1 ถ้าแต่ละบทต่างกันหมด erank ≈ n ใช้เป็นตัวชี้นำว่าควรเพิ่มบทในชนิดใด และควรเผื่อความจุ (rank \(r\)) ของ LoRA แค่ไหน — ไม่ใช่ทฤษฎีบทเรื่อง rank ของ LoRA ต้องยืนยันด้วยการทดลองจริง

        เทคนิค Security ที่ประยุกต์กับ LoRA ในโครงการนี้

        การ fine-tune ด้วย LoRA เพิ่มจุดเสี่ยง 3 จุด: ข้อมูลเทรน, ไฟล์ adapter ที่แชร์กัน และผลลัพธ์ของโมเดล หน้านี้รวบรวมแนวทางฝั่งป้องกันและบอกว่าโครงการนี้ใช้แต่ละข้ออย่างไร (เนื้อหาเพื่อการศึกษา)

        1. ที่มาและความครบถ้วนของข้อมูล

        บันทึกที่มาของทุกบท (ฟิลด์ source) และคำนวณ SHA-256 ของชุดข้อมูลก่อนเทรน เพื่อยืนยันว่าข้อมูลที่ใช้เทรนคือชุดเดียวกับที่ตรวจไว้

        ในโปรแกรม: เครื่องมือด้านล่างคำนวณ hash ของชุดข้อมูลปัจจุบัน

        2. ป้องกันข้อมูลปนเปื้อน (data poisoning)

        งานวิจัยแสดงว่าผู้ไม่หวังดีแทรกตัวอย่างพิษลงชุด instruction tuning ให้โมเดลเปลี่ยนพฤติกรรมเมื่อเจอวลี trigger ได้ และการกรองข้อมูลป้องกันได้เพียงปานกลาง (Wan et al., 2023) อีกงานรายงานว่าพิษเพียง 1% ของ 4,000 ตัวอย่างทำให้ประสิทธิภาพลดราว 80% (Qiang et al., 2024)

        ในโปรแกรม: ใช้ตัวตรวจลายเป็น “ด่านรับข้อมูล” — บทที่อ้างว่าเป็นชนิดใดต้องผ่านกฎของชนิดนั้น และตรวจหาพยางค์ที่โผล่ข้ามหลายชนิดผิดปกติ (ลักษณะคล้าย trigger)

        3. ห่วงโซ่อุปทานของ LoRA adapter

        Adapter ที่แชร์ต่อกันอาจซ่อน backdoor ไว้ใต้ความสามารถปกติ (LoRA-as-an-Attack, 2024; Trojan adapters, NDSS 2025) งานปี 2026 สรุปว่าการตรวจเชิงพฤติกรรม (behavioral detection) เป็นวิธีที่ใช้ได้ทั่วไปสำหรับสแกน adapter (Lelle, 2026)

        ในโปรแกรม: ใช้กลอนทดสอบ + control เป็นชุดทดสอบพฤติกรรม ก่อนนำ adapter ใดมาใช้ ให้วัดคะแนนผ่านกฎเทียบกับก่อนติดตั้ง และเก็บ hash ของไฟล์ adapter

        4. รูปแบบไฟล์น้ำหนักที่ปลอดภัย

        ไฟล์แบบ pickle (เช่น .pt/.bin จาก torch.save) รันโค้ดได้ตอนโหลด (Hugging Face) ส่วน safetensors เก็บเฉพาะ tensor กับ header JSON จึงไม่มีความเสี่ยงรันโค้ด (PyTorch)

        แนวปฏิบัติ: บันทึกและโหลด adapter เป็น .safetensors เท่านั้น

        5. ลายน้ำ vs ลายเซ็นเชิงโครงสร้าง

        Watermark ของ LLM ฝังสัญญาณทางสถิติ (ชุด token “เขียว”) ที่ตรวจได้โดยไม่ต้องเข้าถึงโมเดล (Kirchenbauer et al., 2023)

        เปรียบเทียบเพื่อการศึกษา: กฎกลบทก็เป็นลายเซ็นที่ตรวจได้โดยไม่ต้องใช้โมเดลเช่นกัน แต่มองเห็นได้และแก้ทิ้งง่าย จึงใช้ยืนยัน “รูปแบบ” ได้ ไม่ใช่ยืนยัน “ผู้สร้าง”

        6. การจำข้อมูลเทรน (memorization)

        โมเดลจำลำดับที่หายากในข้อมูลเทรนได้ตั้งแต่ช่วงต้นของการเทรน แม้ไม่ overfit วัดได้ด้วยการแทรก “canary” แล้ววัด exposure (Carlini et al., 2019)

        แนวปฏิบัติ: ใส่กลอน canary สังเคราะห์ 1 บทในชุดเทรน แล้วดูว่า LoRA ท่องกลับมาได้หรือไม่ และวัด n-gram ที่ซ้ำกับข้อมูลเทรน เพื่อแยก “เรียนลาย” ออกจาก “ท่องจำ”

        เครื่องมือตรวจชุดข้อมูลก่อนเทรน

        กดปุ่มเพื่อคำนวณ SHA-256, ตรวจด่านรับข้อมูล และหาพยางค์ที่โผล่ข้ามชนิดผิดปกติ

        โคลงที่นำมาใส่เพิ่ม

        คัดจากสารบัญห้องเรียนโคลงกลบท บ้านกลอนน้อย (59 ชนิด) โดยเลือกเฉพาะกลที่อาศัยคำซ้ำ ซึ่งตัวตรวจแบบ equality ตรวจได้ และเฉพาะบทคลาสสิก (จารึกวัดพระเชตุพนฯ, จินดามณี, โคลงปทุมสังกา)

        ชนิดบทกล (สรุป)ที่มาหมายเหตุ

        ที่ไม่ได้นำมา และเหตุผล

        ชนิดเหตุผล
